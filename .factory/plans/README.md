## Decisions behind these plans (2026-11-24)

- Project knowledge comes from read-only agent access, not a snapshot built by Grillado.
- Prototypes start as previews on options; real builds in worktrees are a later phase.
- Grillado hands off to the coding agent and listens back; it does not run the build.
- Code grounding ships first.
- Coding agents drive Grillado through CLI commands with no setup; MCP stays as an option.
- The README is an install guide plus agent integration; everything else moves to `docs/`.

## Findings considered and rejected

- A Grillado-built project snapshot with tools kept off: too shallow, the agent cannot follow
  a lead into the code.
- Real throwaway builds as the first form of prototyping: needs write access before the
  product has earned that trust.
- Grillado driving the build itself: turns a planning tool into a build tool.
- Claude Code `--restricted` for the read variant: it also ignores user settings, which can
  hold a sign-in key helper. `--setting-sources user` plus an explicit tool list is used
  instead (see 002, Maintenance notes).
